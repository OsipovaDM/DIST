## ЦЕЛЬ
Реализовать систему распознавания ПДн из **10 атрибутов чётного варианта КР**:
1. SURNAME — Фамилия
2. NAME — Имя
3. INN — ИНН (12 цифр, проверка контрольного разряда по алгоритму ФНС)
4. PASSPORT — Серия и номер паспорта РФ (4+6 цифр, проверка серии по белому списку регионов)
5. CREDIT_CARD — Номер банковской карты (16 цифр, проверка по алгоритму Луна)
6. OGRNIP — ОГРНИП (15 цифр, контрольный разряд: (int(первые 14) % 13) % 10)
7. IP — IPv4-адрес (4 октета 0–255)
8. EMAIL — E-mail
9. BIRTH_CERT — Номер свидетельства о рождении (римская серия I–XV + опц. 2 буквы субъекта + 6–7 цифр)
10. KLADR — Код КЛАДР (13 или 17 цифр, первые 2 — валидный код региона РФ)

**ВНИМАНИЕ:** PATRONYMIC, PHONE, SNILS в чётном варианте КР **НЕ РАСПОЗНАЮТСЯ**.
Отчество в обучении BERT **не используется**, только SURNAME и NAME.

## АРХИТЕКТУРА (комбинированный подход, лекция 2)
- **ФИО (SURNAME, NAME)** — через дообучение BERT (rubert-base-cased) как
  задачу token classification / NER.
- **Остальные 8 атрибутов** — через правила: регулярные выражения + проверка
  контрольных разрядов + структурные проверки.
- **Объединение результатов ИИ и правил:** при конфликте приоритет у правила;
  если обе системы нашли один атрибут — берём с более длинным спаном.
  Соблюдается требование «один токен — один атрибут».
- **Схема разметки BIO** (B-XXX, I-XXX, O). Каждый токен относится максимум
  к одному атрибуту.

## ТРЕБОВАНИЯ КР (проверять в коде автоматически!)
- **Weighted F1 ≥ 0.85** (средневзвешенное по атрибутам).
- **Mean F1 ≥ 0.80** (простое среднее по атрибутам, добавлено в КР).
- **Тестовых текстов на каждый атрибут ≥ 50** (генерация через Faker + ручные
  шаблоны; Faker — ТОЛЬКО для тестирования, НЕ для обучения).
- **Тестовый набор суммарно ≥ 100 текстов.**
- Выход программы: список кортежей `[("ATTR_NAME", start_idx, end_idx), ...]` —
  индексы в исходном тексте.
- Для структурированных атрибутов обязательна проверка контрольных разрядов
  (ИНН, ОГРНИП, банковская карта, серия паспорта, код региона КЛАДР).
- **Тестирование на factRuEval-2016 testset** — независимая оценочная коллекция,
  не участвовавшая в обучении.
- В конце ноутбука — блок assert'ов, проверяющих все условия приёмки.

## ОБУЧЕНИЕ МОДЕЛИ (лекция 2)
- Базовая модель: `DeepPavlov/rubert-base-cased`.
- Датасет: factRuEval-2016 (скачивается по URL
  `https://github.com/dialogue-evaluation/factRuEval-2016/archive/master.zip`).
- **Явное разделение:** `devset/` → обучение + валидация (сплит 80/20),
  `testset/` → независимый тест. Папки читаются **раздельно** через
  `load_factru(FACT_DIR, sets=["devset"])` и `load_factru(FACT_DIR, sets=["testset"])`.
  **НЕ фильтровать по `rec.url`** — в corus url не содержит имя папки.
- **Разметка ФИО в factRuEval:** используется `firstname` → `NAME`,
  `surname` → `SURNAME`. `patronymic` **игнорируется** (отчество не входит
  в чётный вариант).
- Дообучение через HuggingFace Trainer + TrainingArguments:
  - `learning_rate = 2e-5`
  - `per_device_train_batch_size = 16`
  - `num_train_epochs = 7` (при 7 эпохах модель выходит на плато, F1 не растёт)
  - `weight_decay = 0.01`
  - `eval_strategy = "epoch"`
  - `save_strategy = "epoch"`
  - `save_total_limit = 1` (экономия диска — иначе чекпоинты занимают ~2.8 ГБ)
  - `load_best_model_at_end = True`
  - `metric_for_best_model = "f1"`
  - `report_to = "none"` (в transformers 5.x `None` не принимается)
  - `warmup_ratio = 0.1` (плавный старт LR)
  - `lr_scheduler_type = "cosine"` (плавное затухание)
  - `dataloader_num_workers = 0` (Windows-safe)
- **Версионная независимость:** через `inspect.signature` проверять наличие
  `eval_strategy` vs `evaluation_strategy`, `tokenizer` vs `processing_class`,
  `save_safetensors`.
- Токенизация WordPiece, разбиение на батчи (учти лимит длины 512).
- **MAX_LEN = 256** длина последовательности в токенах после токеницации
- Оценка через `seqeval`: precision, recall, F1 (weighted).

## ЧАНКИНГ ДЛЯ ДЛИННЫХ ДОКУМЕНТОВ (обязательно)
В `model_entities` текст режется на перекрывающиеся чанки по MAX_LEN токенов
со stride = chunk_size // 2 (перекрытие 50%). Это нужно, потому что документы
factRuEval длиннее 256 токенов, и без чанкинга половина ФИО в хвосте не
находится (recall падает с 0.94 до 0.58). Offsets корректируются на начало
чанка, дубли удаляются через `seen: set`.

## ПРАВИЛА ДЛЯ СТРУКТУРИРОВАННЫХ АТРИБУТОВ
Приведи регулярные выражения + функции проверки контрольных разрядов.
**Явно определи форматы для каждого атрибута с разными разделителями.**

### Форматы
- **EMAIL:** `(?i)([a-z0-9а-яё_.+\-]+@[a-zа-яё\d][a-zа-яё\d.\-]*\.[a-zа-яё]{2,})`
- **IP:** `(?<![\d.])(?:(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)\.){3}(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)(?!\.?\d)`
  **ВНИМАНИЕ:** lookahead `(?!\.?\d)` — обязателен, чтобы IP с точкой в конце
  предложения («IP: 192.168.1.100.») матчился. Если использовать `(?![\d.])`,
  IP на конце предложения не находится (F1 = 0).
- **ИНН:** 12 цифр; разделители пробел/дефис; контроль по коэффициентам
  `[7,2,4,10,3,5,9,4,6,8]` (11-я цифра) и `[3,7,2,4,10,3,5,9,4,6,8]` (12-я).
- **CREDIT_CARD:** 16 цифр; разделители пробел/дефис; алгоритм Луна.
- **PASSPORT:** серия 4 цифры + номер 6 цифр; разделители пробел/дефис/без;
  белый список регионов РФ (первые 2 цифры серии).
- **OGRNIP:** 15 цифр; контроль: `(int(first_14) % 13) % 10 == int(d[14])`.
- **BIRTH_CERT:** `(?<![А-ЯЁA-Z\d])([IVX]{1,4})[\s\-]?(?:[А-ЯЁA-Z]{2}[\s\-]?)?(\d{6,7})(?!\d)`
  (римская серия + опц. буквы субъекта + номер).
- **KLADR:** 13 или 17 цифр; проверка первых 2 цифр по белому списку регионов.

### Функции проверки
- `validate_inn(digits) -> bool`
- `validate_luhn(card_number) -> bool`
- `validate_passport_series(series) -> bool`
- `validate_ogrnip(digits) -> bool`
- `validate_kladr(digits) -> bool`

## МЕТРИКИ
- `precision = tp / (tp + fp)`
- `recall = tp / (tp + fn)`
- `F1 = 2 * precision * recall / (precision + recall)`
- `weighted F1` — среднее F1 по атрибутам, взвешенное по числу истинных
  примеров (tp + fn) каждого атрибута.
- `mean F1` — простое среднее F1 по 10 атрибутам.
- Пороги: **weighted F1 ≥ 0.85, mean F1 ≥ 0.80.**
